# Sunrise Java Bridge — lab 0.1
Independent of RustPG and Hand of God. Desktop proof of concept only. Java 17 JAR containing a purpose-built bridge entry point is loaded by a JVM created from Rust (JNI 0.21.1, matching the version already used by Sunrise Android). Rust calls the Java tick event; Java calls Rust's native protocol function; Java returns a request; Rust rejects out-of-range requests. The health is a test fixture, not game state. No arbitrary external JAR execution, Minecraft class emulation, Forge/Fabric/NeoForge, SMOD, Android or runtime integration is claimed. The fixture is trusted code from this repository; JVM classloaders are not a security sandbox. Never run untrusted jars inside the game process.

## Android route
Sunrise Android uses NativeActivity and JNI 0.21.1 already. Android ART is not the desktop JVM and cannot directly load arbitrary JVM class-file JARs; choose either an explicit compatible OpenJDK runtime (launcher-level integration, ABI/resource checks) or DEX compilation and an Android-compatible Java API (not general Java mod support). First prove round-trip through the existing Android JavaVM, then connect a genuine server tick hook, bound work off the render thread, and apply validated intents on the server. Preserve exact pinned SDK and separate lab from stable release.

## Future compatibility
Map versioned Minecraft classes, Fabric/Forge registries, events, networking, resources and render APIs. Native Sunrise mixins can supplement missing hooks, but Java bytecode mixins cannot patch Rust automatically. Start with source-level ports and data assets, then one explicitly targeted Java loader API subset. Need permission/licensing review for redistributing third-party mods. Desktop fixture is not evidence of mobile performance.
