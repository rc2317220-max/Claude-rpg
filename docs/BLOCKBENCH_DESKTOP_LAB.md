# Blockbench Desktop MCP lab
Separate from the prior file-based studio and from the game. Actual Blockbench 5.2.2 desktop Electron, pinned RenasDemirbas MCP 6a54fb47bb801f6dcf7fd979eee8aad51a1f7842, Xvfb with software graphics. Source built with lockfile, desktop deb SHA256 verified. Local-only MCP bridge and CDP bootstrap; no tunnel, no API key, no Codespaces. GitHub Actions ephemeral runs; not an always-on MCP connection to ChatGPT. No arbitrary command execution in JSON. The assistant writes reviewed batches in .agent/blockbench-desktop-commands.json, runs workflow, downloads images and transcript, inspects actual viewport, then writes the next batch. Each successful batch saves .bbmodel and manifest in checkpoint/. On manual dispatch specify resume_run and resume_artifact, then open $INPUT/checkpoint/<name>.bbmodel using project_file action open. For importing older goblins, specify source artifact and exact .bbmodel path from it; use native open and preserve textures. Do not modify game release until separately integrated.

## First smoke
Create simple fixture (not production goblin), build via MCP, paint, animate, capture multiple views and frames, save, close, reopen, assert counts, capture Electron UI and X11 desktop. Artifacts include tools.json (exact live schemas), status.json, transcript.json, individual PNGs, checkpoint, summary and diagnostics even on failure. Verify plugin connected, nonempty images and differing animation images; actual visual inspection still required. This workflow does not use the previous CPU renderer. No runtime claim until Starling test.

## Editing loop
Keep command batches small (e.g. modify face and capture two views, or edit one attack and render selected frames). Start from a saved checkpoint in the previous artifact. GitHub Actions runner cannot be kept indefinitely; restore model for each round. The tool allowlist supports real model, texture, UV, animation, rigging, inspection, reference, save/open. Arbitrary eval_code and run_action are intentionally excluded from the automated batch interface. Additional tools can be reviewed against tools.json and added if needed. Use explicit names and labels; do not include tokens or external secrets in JSON. No need for user terminal.

Desktop editing recording: run.sh records the real X11 window with FFmpeg. The queue contains a newly authored goblin family scaffold and individual attack studies. Use screenshots and recordings to review before completing; no live stream is exposed.
